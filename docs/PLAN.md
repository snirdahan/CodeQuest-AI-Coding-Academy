## 1. ארכיטקטורת המוצר

### העיקרון המנחה
הכי פשוט שעדיין בטוח, וזול להפעלה. שרת אחד (Next.js) שמגיש גם את האתר וגם את ה־API, מסד נתונים אחד, ו"מריץ קוד" מבודד שאפשר להוציא לשירות נפרד כשנגדל.

```
┌──────────────────────┐        ┌────────────────────────────┐
│  דפדפן (React/Next)  │◄──────►│  שרת Next.js (API routes)  │
│  עורך קוד CodeMirror │  HTTPS │  התחברות, התקדמות, XP       │
└──────────────────────┘        │  תוכן הקורסים (קוד TS)      │
┌──────────────────────┐        │                            │
│ תוסף VS Code (TS)    │◄──────►│  /api/ext/* (טוקן Bearer)   │
│ פאנל תרגיל + בדיקה    │        └──────┬──────────────┬──────┘
└──────────────────────┘               │              │
                                       ▼              ▼
                          ┌──────────────────┐  ┌───────────────────────┐
                          │ מסד נתונים SQLite │  │ Lua Sandbox Runner    │
                          │ (בעתיד: Postgres) │  │ תהליך נפרד, Lua 5.4    │
                          └──────────────────┘  │ ב־WebAssembly, בלי     │
                                                │ גישה לקבצים/רשת/מערכת │
                                                └───────────────────────┘
```

| שכבה | טכנולוגיה | למה |
|---|---|---|
| אתר | Next.js 16 + React 19 + TypeScript + Tailwind CSS 4 | סטנדרט תעשייתי, אתר ו־API בפרויקט אחד |
| עורך קוד בדפדפן | CodeMirror 6 | קל, תומך Lua/HTML/CSS, עובד טוב עם RTL מסביב |
| מסד נתונים | SQLite (better-sqlite3) בשלב הפיתוח והבטא | אפס עלות ואפס הרשמה. כל הגישה עוברת דרך שכבת `db.ts` אחת, כך שמעבר ל־Supabase/Postgres הוא החלפה של קובץ אחד |
| התחברות | אימייל + סיסמה, scrypt, עוגיית session מסוג httpOnly | אין תלות בספק חיצוני. בהמשך אפשר להוסיף Google/Discord |
| הרצת Lua | wasmoon (Lua 5.4 האמיתי, מקומפל ל־WebAssembly) בתהליך בן נפרד | ראו סעיף אבטחה |
| הרצת HTML/CSS | iframe עם `sandbox` בדפדפן של הלומד | הקוד לא רץ על השרת בכלל |
| תוסף | VS Code Extension API רשמי, TypeScript | |
| בדיקות | Vitest (יחידה + בדיקות פתרונות אמיתיות) | |

### אבטחת הרצת קוד (סעיף 7)
- קוד של לומד **אף פעם** לא רץ בתוך תהליך השרת. כל בדיקה פותחת תהליך Node נפרד (`runner/lua-sandbox.mjs`) עם הגבלת זיכרון.
- בתוך התהליך רץ Lua אמיתי ב־WebAssembly, **בלי** הספריות `io`, `os`, `debug`, `package`, `require`, `dofile`, `loadfile`, `load`. אין לו גישה לקבצים, לרשת או לפקודות מערכת.
- מגבלת הוראות (instruction hook) עוצרת לולאות אינסופיות, ובנוסף טיימר קשיח הורג את התהליך אחרי 3 שניות.
- הפלט מוגבל בגודלו.
- **לפני פרודקשן ציבורי** מומלץ להעביר את ה־runner לשירות נפרד (קונטיינר משלו, למשל Fly.io / Cloud Run) כך שגם אם יימצא באג ב־WebAssembly, הוא לא באותה מכונה של מסד הנתונים.
- Java (בעתיד): דורש JVM בקונטיינר מבודד – לא ירוץ על שרת האתר.
- FiveM: התנהגות מנוע אמיתית (Natives, אירועי רשת) דורשת שרת FiveM אמיתי. בפלטפורמה נבדוק רק את חלקי ה־Lua הטהורים, ונאמר במפורש מה חייב שרת FiveM.
- Roblox: Luau ≠ Lua. כל מה שקשור ל־Instances/Services דורש Roblox Studio. נאמר זאת בכל שיעור רלוונטי.

### AI Mentor (שלב 5, ⏳)
- ספק: Claude API דרך השרת בלבד (המפתח לעולם לא אצל הלקוח).
- לפני AI: רמזים דטרמיניסטיים מתוך התוכן (חינם, מיידי). AI נכנס רק כשהלומד מבקש אחרי ניסיון.
- מכסות: חינם – מעט בקשות ביום; פרימיום – יותר. מטמון לפי (תרגיל + שגיאה מנורמלת).
- נשלח רק קוד התרגיל שהלומד בחר, אחרי הסכמה מפורשת. לעולם לא קבצים אחרים מהמחשב.

### תשלומים (שלב 5, ⏳ – דורש החלטה שלך)
Stripe לא פתוח לעסקים ישראליים. אפשרויות לגיטימיות:
- **Paddle** או **Lemon Squeezy** – "Merchant of Record": הם גובים, מטפלים במע"מ וחשבוניות, ומאפשרים מנוי חודשי + ביטול עצמי. מתאים למכירה גם מחוץ לישראל.
- **Grow (משולם) / Cardcom / Tranzila** – סליקה ישראלית, מתאים אם השוק ישראלי בלבד.
בינתיים מסך השדרוג אוסף "הרשמה לגישה מוקדמת" אמיתית – זה כבר נתון למבחן מחיר, בלי לגבות כסף.

## 4. קורס Lua ראשון – "Lua מאפס"

| # | שיעור | מטרת למידה | האתגר | איך נבדק | חינם? |
|---|---|---|---|---|---|
| 1 | שלום עולם | להריץ פקודה ראשונה ולהבין `print` | להדפיס ברכה | יש לפחות שורת פלט אחת, נעשה שימוש ב־print | ✅ |
| 2 | משתנים | לשמור מידע בשם | משתנה עם שם משתמש והדפסתו | קיים `local` עם מחרוזת, והערך שלו באמת הודפס | ✅ |
| 3 | מספרים וחשבון | פעולות חשבון | חישוב מחיר כולל | הפלט שווה לחישוב, ולא מספר שהוקלד ידנית | ✅ |
| 4 | מחרוזות | חיבור טקסטים `..` ו־`#` | בניית משפט מכמה משתנים | פלט נכון + שימוש ב־`..` | ✅ |
| 5 | תנאים | `if / elseif / else` | פונקציה שמחזירה דירוג לפי ציון | נקראת עם 6 ציונים נסתרים | ✅ |
| 6 | לולאות | `for` מספרית ו־`while` | סכום 1..n | נקראת עם ערכי n נסתרים | פרימיום* |
| 7 | פונקציות | פרמטרים וערכי החזרה | `clamp(x,min,max)` | בדיקות נסתרות כולל מקרי קצה | פרימיום* |
| 8 | טבלאות כרשימה | מערכים, `#`, `ipairs` | ממוצע של רשימה | רשימות נסתרות, כולל רשימה ריקה | פרימיום* |
| 9 | טבלאות כמילון | מפתח־ערך, `pairs` | מלאי של שחקן | בדיקת התנהגות על מלאים שונים | פרימיום* |
| 10 | פרויקט מסכם | חיבור הכול | מערכת XP קטנה למשחק | סדרת בדיקות התנהגות | פרימיום* |

\* בשלב הבטא כל 10 השיעורים פתוחים לכולם כדי שנוכל ללמוד מהמשתמשים; הסימון "פרימיום" מוצג אבל ניתן לשלוט בו מקובץ התוכן בשורה אחת.

**מסלולים נוספים ב־Lua:**
- **FiveM** (⏳ שלב 4): client/server scripts, `fxmanifest.lua`, אירועים (`RegisterNetEvent`, `TriggerServerEvent`), פקודות (`RegisterCommand`), threads (`CreateThread`, `Wait`). Lua טהור נבדק בפלטפורמה; מה שדורש מנוע – מסומן "דורש שרת FiveM".
- **Roblox Luau** (⏳ שלב 6): הבדלים בין Luau ל־Lua (טיפוסים, `continue`, `+=`), ושימוש ב־Roblox Studio.

## 5. תכנון תוסף VS Code (אינטגרציה אמיתית)

### זרימת המשתמש
1. באתר, בשיעור, לוחצים **"תרגל ב־VS Code"**.
2. השרת יוצר **קוד חיבור חד־פעמי** (תקף 10 דקות) ופותח קישור `vscode://codequest.codequest/open?exercise=…&pair=…`.
3. VS Code נפתח, התוסף מקבל את הקישור. אם הוא עוד לא מחובר – הוא מחליף את קוד החיבור בטוקן (`POST /api/ext/pair`) ושומר אותו ב־**SecretStorage** המוצפן של VS Code.
4. התוסף מוריד את התרגיל (`GET /api/ext/exercises/:id`) ויוצר קובץ **רק** בתיקייה ייעודית: `~/CodeQuest/<course>/<lesson>.lua`. הוא לא נוגע בקבצים אחרים.
5. פאנל צד מציג את ההוראות, רמזים ותוצאות.
6. הלומד כותב קוד ולוחץ **"Check Solution"** (כפתור בפאנל, או בשורת הכותרת של הקובץ).
7. התוסף שולח **רק את תוכן קובץ התרגיל** ל־`POST /api/ext/exercises/:id/check`.
8. השרת מריץ את אותו בודק בדיוק כמו באתר, שומר התקדמות ו־XP, ומחזיר תוצאה.
9. התוסף מציג הצלחה/שגיאות (כולל סימון שורה בעורך במקרה של שגיאת תחביר) ומציע **"לשיעור הבא"**.
10. באתר – הדשבורד מתעדכן מיידית (אותו מסד נתונים).

### אבטחה
- הטוקן אקראי (256 ביט), נשמר בשרת רק כ־hash (SHA-256). אפשר לבטל אותו ממסך "חיבור VS Code".
- קוד חיבור חד־פעמי, תקף 10 דקות, נמחק אחרי שימוש.
- התוסף לא מריץ שום קוד מקומי ולא קורא קבצים מחוץ לתיקיית התרגיל.

### פקודות התוסף
`CodeQuest: Connect Account`, `CodeQuest: Open Exercise`, `CodeQuest: Check Solution`, `CodeQuest: Show Hint`, `CodeQuest: Next Lesson`, `CodeQuest: Disconnect`.

## 6. מבנה תיקיות

```
codequest/
├── docs/                    מסמכי תכנון, הוראות התקנה, תוכנית השקה
├── web/                     האתר + ה־API
│   ├── runner/              Lua sandbox (תהליך נפרד)
│   ├── src/
│   │   ├── app/             מסכים (App Router) ו־API routes
│   │   ├── components/      רכיבי עיצוב משותפים
│   │   ├── content/         תוכן הקורסים – שפה ← מסלול ← קורס ← שיעור
│   │   │   ├── catalog.ts   כל השפות והמסלולים (כולל "בקרוב")
│   │   │   └── lua/         שיעורי Lua
│   │   ├── lib/
│   │   │   ├── db.ts        כל הגישה למסד הנתונים
│   │   │   ├── auth.ts      התחברות ו־sessions
│   │   │   ├── grading/     מנוע הבדיקה
│   │   │   └── gamification.ts  XP, רמות, רצף, הישגים
│   └── tests/               בדיקות אוטומטיות
└── vscode-extension/        התוסף
    ├── src/extension.ts
    └── test/
```

**איך מוסיפים שפה חדשה (למשל Python):** מוסיפים רשומה ב־`catalog.ts`, תיקיית תוכן, ו"בודק" (grader) שמתאים לשפה. שאר המערכת (XP, התקדמות, תוסף) לא משתנה.
